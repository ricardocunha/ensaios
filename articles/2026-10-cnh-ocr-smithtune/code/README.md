# cnh-ocr-smithtune

Reading Brazilian driver's licenses (CNH) with open models. It's also a hands-on test of **[smithtune](https://github.com/langchain-ai/smithtune)**, LangSmith's new fine-tuning CLI (v0.1.0, released 2026-09-24).

```
 CNH image ─► [ Reader ]  ─► Transcription ─► [ Extractor ] ─► CNH Record (validated JSON)
              vision OCR model                  text-only tool-calling agent
              LoRA on Apple Silicon (mlx-vlm)   Teacher (Claude Sonnet 5) → Student (Qwen3.5-9B)
                                                distilled with smithtune on Baseten
```

**Why two stages?** smithtune v0.1 [filters out every trajectory that contains images](docs/SMITHTUNE_NOTES.md) and can only train a fixed list of text LLMs. So the vision part is fine-tuned with Hugging Face / MLX tooling, and smithtune does what it was built for: distilling an agent's behavior. See [ADR-0001](docs/adr/0001-two-stage-reader-extractor.md).

> ⚠️ **All training data is synthetic.** Every image says *AMOSTRA / SYNTHETIC*, the layout is deliberately not a replica, and the CPF and CNH numbers are random (with valid checksums). Never commit real documents ([ADR-0002](docs/adr/0002-synthetic-training-data-only.md), LGPD).

## Results so far (Stage 1: Reader)

Full tables are in [`docs/RESULTS.md`](docs/RESULTS.md), generated by `make report`. Accuracy is measured on CNHs only; rejections are reported separately. The BID results are on **real CNH templates**, scanned and often rotated, from the BID Dataset.

| Reader | Synthetic test: label acc | **BID: label acc** | BID: real CNHs wrongly rejected | BID: RG/CPF rejected | s/img (M4 Pro) |
|---|---|---|---|---|---|
| PaddleOCR-VL-1.6 (0.9B), zero-shot | 17.4% | 0.0% | 0/70 | 0/72 | 1.2 |
| Chandra 2 (~5B), zero-shot | 17.3% | – | – | – | 51.0 |
| Qwen3.5-9B, zero-shot | 72.4% | 48.2% | 5/70 | 59/72 | 7.1 |
| PaddleOCR-VL + LoRA, round 1 (one card design) | 99.8% | 32.0% | 48/70 | 72/72 | 0.6 |
| **PaddleOCR-VL + LoRA, round 2 (domain-randomized)** | **99.8%** | **52.3%** | **30/70** | **72/72** | **0.9** |

What we learned:
- **Zero-shot, the specialists read but don't follow instructions.** Chandra 2 finds 100% of values but always writes its own HTML layout, and PaddleOCR-VL writes free text and loops. Generalist Qwen3.5-9B follows the format.
- **Synthetic scores can't tell good from bad.** Rounds 1 and 2 both score 99.4–99.8% on every synthetic set, but they differ by 20 points on real templates. Round 1 learned "CNH = my renderer's look" and rejected 48 of 70 real CNHs, yet read 92.9% of labels correctly on the ones it accepted.
- **Variety beats volume.** With the same 2,293 images made less alike (palettes, fonts, layouts, scans, 90°/180°/270° turns, CNH-like decoys), real-template accuracy went from 32.0% to 52.3%. That's ahead of zero-shot Qwen3.5-9B at about 8× the speed. Still open: 30 of 70 real CNHs are rejected.
- **mlx-vlm 0.7.3 gotcha:** its LoRA doesn't freeze PaddleOCR-VL's vision tower (named `visual`), so it trains 49.8% of the model and runs out of memory. [`reader/mlx_lora.py`](src/cnh_ocr/reader/mlx_lora.py) fixes it: 1.3% trainable, 5.7 GB peak, about 1h45 per epoch.

Stage 2 (Extractor + smithtune) results: *pending.* Running notes are in [`docs/SMITHTUNE_NOTES.md`](docs/SMITHTUNE_NOTES.md).

## Quickstart

```bash
uv sync --all-extras
make test

# Stage 1: free, local (Apple Silicon)
make data                          # round-2 synthetic set: 2,293 train + 300 test, ~1 min
make data-v1                       # round-1 set + hard set (single design), ~45 min
make bid                           # BID sample → data/bid/test (cited, not redistributed)
make zero-shot                     # all three Readers on synthetic + BID
make train-reader                  # PaddleOCR-VL LoRA on round-2 data (TAG=v1 for round 1)
make eval-reader                   # synthetic test, hard set, BID
make report                        # → docs/RESULTS.md

# Stage 2: paid; fill in .env first (cp .env.example .env)
make teacher LIMIT=20              # check the cost, then: make teacher
./smithtune/run.sh install && ./smithtune/run.sh doctor
./smithtune/run.sh pull-golden && ./smithtune/run.sh push-golden
./smithtune/run.sh triage-sample   # council vs ground truth (cnh_ocr.evaluation.council_agreement)
./smithtune/run.sh prepare && ./smithtune/run.sh plan && ./smithtune/run.sh train
./smithtune/run.sh evaluate && ./smithtune/run.sh deploy && ./smithtune/run.sh student-eval
./smithtune/run.sh undeploy        # don't forget: deployments bill until removed
```

## Layout

| Path | What |
|---|---|
| `CONTEXT.md` | Glossary: Reader, Transcription, Extractor, CNH Record, Teacher, Student, Golden Trajectory… |
| `src/cnh_ocr/synth/` | Synthetic CNH generator. `--style v1` is one design; `--style v2` is domain-randomized (palettes, fonts, layouts, scans, rotations, CNH-like decoys), built in parallel shards |
| `src/cnh_ocr/reader/` | The three Base OCR Models, mlx-vlm inference, LoRA/QLoRA training (`mlx_lora.py` carries the vision-freeze fix) |
| `src/cnh_ocr/extractor/` | Extractor agent (LangChain `create_agent`), 8 tools, OCR-noise injector, LangSmith-traced runner with ground-truth feedback |
| `src/cnh_ocr/evaluation/` | Metrics (tolerant label matching), report, BID loader, smithtune council-vs-ground-truth agreement |
| `smithtune/` | `run.sh` (every smithtune step; paid steps gated) + triage `rubric.md` |
| `docs/` | ADRs, smithtune field notes, results |
